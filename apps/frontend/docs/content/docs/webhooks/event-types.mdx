Reloop supports several event types that you can subscribe to. Each event has a specific payload structure.

## Email Events
| Event | Description |
|-------|-------------|
| `email.sent` | Triggered when an email is successfully sent. |
| `email.delivered` | Triggered when an email is successfully delivered. |
| `email.bounced` | Triggered when an email bounces. |
| `email.opened` | Triggered when a recipient opens an email. |
| `email.clicked` | Triggered when a recipient clicks a link. |
| `email.complained` | Triggered when a recipient marks as spam. |
| `email.failed` | Triggered when an email fails to send. |
| `email.received` | Triggered when an inbound email is received. |

## Domain Events
| Event | Description |
|-------|-------------|
| `domain.created` | Triggered when a new domain is created. |
| `domain.updated` | Triggered when a domain's status is updated. |
| `domain.deleted` | Triggered when a domain is deleted. |

## Contact Events
| Event | Description |
|-------|-------------|
| `contact.created` | Triggered when a new contact is created. |
| `contact.updated` | Triggered when a contact is updated. |
| `contact.deleted` | Triggered when a contact is deleted. |

### Generic Payload Structure
Every webhook payload follows a consistent top-level structure:

```json
{
  "type": "event.name",
  "created_at": "2023-01-01T12:00:00Z",
  "data": {
    "id": "id_123456789",
    "status": "active",
    "timestamp": "2023-01-01T12:00:00Z"
  }
}
```
