Use Reloop to send Supabase signup confirmations, invitations, magic links,
password recovery emails, email-change confirmations, and reauthentication codes.

## Prerequisites

- A [Supabase](https://supabase.com) project with the Email provider enabled
- A verified sending domain and an API key with mail-send permission in the
  [Reloop dashboard](https://reloop.sh/dashboard)
- A sender address on that verified domain

## Send Email hook

Reloop includes a deployable Supabase Edge Function in
[`integrations/supabase`](https://github.com/reloop-labs/reloop/tree/main/integrations/supabase).
It verifies signed Auth hooks, sends through the Reloop HTTP API, and supplies
idempotency keys so retries reuse the same sends.

<Steps>
  <Step title="Deploy the function">
    Install the [Supabase CLI](https://supabase.com/docs/guides/local-development/cli/getting-started),
    clone the Reloop repository, and run:

    ```bash
    cd integrations/supabase
    supabase login
    supabase link --project-ref YOUR_PROJECT_REF
    supabase functions deploy reloop-send-email --no-verify-jwt
    ```
  </Step>
  <Step title="Create a signed Auth hook">
    In Supabase, open **Authentication > Hooks** and add a **Send Email** HTTP
    hook with this URL:

    ```text
    https://YOUR_PROJECT_REF.supabase.co/functions/v1/reloop-send-email
    ```

    Generate a hook secret and leave the hook disabled until the next step is complete.
  </Step>
  <Step title="Configure secrets and enable the hook">
    Create an ignored `.env.hook` file in `integrations/supabase`:

    ```dotenv
    RELOOP_API_KEY=YOUR_RELOOP_API_KEY
    RELOOP_FROM="Example <auth@example.com>"
    SEND_EMAIL_HOOK_SECRET="v1,whsec_YOUR_GENERATED_SECRET"
    ```

    Upload it, then enable the hook in Supabase:

    ```bash
    supabase secrets set --env-file .env.hook
    ```

    Supabase supplies `SUPABASE_URL`. To use self-hosted Reloop, add
    `RELOOP_API_URL=https://reloop.example.com/api/mail/v1/send` to the secrets file.
  </Step>
  <Step title="Test authentication emails">
    Trigger each Auth flow in a test project. Check Reloop's email logs and the
    receiving inbox, then use the code or link in your application. For Secure
    Email Change, confirm that both the current and new address receive their
    own confirmation message.
  </Step>
</Steps>

<Note>
The function authenticates requests with the hook signature, so JWT verification
is disabled for this endpoint. Keep both secrets server-side. An enabled Send
Email hook replaces SMTP delivery and uses the function's plain-text messages,
not Supabase's dashboard email templates. Security notification action types
require extending the handler before enabling those notifications.
</Note>

Set Supabase's Site URL and redirect allowlist to your application URLs. The
function sends verification links to Supabase's `/auth/v1/verify` endpoint and
includes the Auth request's redirect URL. Provider errors return a hook error
rather than reporting a successful send.

## SMTP alternative

To keep Supabase's built-in email templates, disable the Send Email hook and
configure **Authentication > Email > SMTP Settings** instead:

| Setting | Value |
|---------|-------|
| Host | `smtp.reloop.sh`, or your Reloop submission hostname |
| Port | `587` with STARTTLS |
| Username | `reloop` |
| Password | Your Reloop API key |
| Sender email | An address on your verified domain |
| Sender name | Your application's name |

The SMTP hostname must present a trusted TLS certificate. A default self-hosted
installation uses a self-signed certificate; configure a trusted certificate or
use the HTTPS hook. Port `465` in the repository's default SMTP configuration
also uses STARTTLS, so do not assume it provides implicit TLS.
