Welcome to the local development setup guide for Reloop. Reloop is a high-performance, type-safe email and campaign automation platform designed as a modern **monorepo**. 

This document provides a clear, sequential path for both developers and automated agents to set up and run all services in a local environment.

---

## Prerequisites

Before starting, ensure that you have the following installed on your machine:

- **Bun**: The fast all-in-one JavaScript runtime (v1.3.0+) &rarr; [Install Bun](https://bun.sh/get)
- **Docker & Docker Compose**: To run PostgreSQL, Redis, ClickHouse, etc. &rarr; [Install Docker Desktop](https://www.docker.com/products/docker-desktop/)
- **Git**: For cloning the repository

---

## Interactive Walkthrough

Follow these steps sequentially to set up and run Reloop locally.

<Steps>
<Step title="Clone and Install Dependencies">

Clone the Reloop repository and install the dependencies from the root directory using Bun:

```bash
git clone git@github.com:reloop-labs/reloop.git
cd reloop
bun install
```

</Step>

<Step title="Configure Local Domain (Hosts File)">

To support secure local sessions and cookie-sharing across multiple microservices without running into CORS issues, you must map `local.reloop.sh` to your local machine (`127.0.0.1`).

<CodeGroup>
  <CodeBlock title="macOS & Linux">
  ```bash
  echo "127.0.0.1 local.reloop.sh" | sudo tee -a /etc/hosts
  ```
  </CodeBlock>
  <CodeBlock title="Windows (PowerShell - Run as Administrator)">
  ```powershell
  Add-Content -Path $env:windir\System32\drivers\etc\hosts -Value "127.0.0.1`tlocal.reloop.sh"
  ```
  </CodeBlock>
</CodeGroup>

<Callout type="warn" title="System Privileges Required">
  This command edits system configuration files. You may be prompted to enter your administrator or system password.
</Callout>

</Step>

<Step title="Start Docker Infrastructure">

Reloop relies on backing services (PostgreSQL, Redis, ClickHouse, Loki, Grafana, and Caddy). Ensure Docker is running, then boot the entire local stack from the root directory:

```bash
bun docker:up
```

*If you prefer to run Docker Compose manually, you can also run:*
```bash
cd local && docker compose up -d && cd ..
```

This starts:
- **PostgreSQL** (`5432`): Core database for users, authentication, and platform metadata.
- **Redis** (`6379`): In-memory cache, background worker queue, and session store.
- **ClickHouse** (`8123`): High-performance column-oriented analytics and event log database.
- **Caddy** (`80` / `443`): Automatic SSL and reverse-proxy routing.
- **Grafana & Loki** (`3000` / `3100`): Systems dashboards and centralized log aggregation.

</Step>

<Step title="Initialize the Database">

With Docker services running, run the following commands from the **root directory** to apply the database schema (using Drizzle ORM) and seed the initial/default data:

```bash
# Push the schema changes directly to your local database
bun db:push

# Populate the database with required default and initial seeding data
bun db:seed
```

<Callout type="tip" title="Drizzle Studio">
  You can visually explore or edit your database tables anytime by opening Drizzle Studio:
  ```bash
  bun db:studio
  ```
</Callout>

</Step>

<Step title="Configure Environment Variables">

Backend and frontend services look for `.env` files inside their respective subdirectories. For local development, copy the `.env.example` configurations.

For the **Authentication Service** (as an example):
```bash
cp apps/backend/auth/env.example apps/backend/auth/.env
```

<Callout type="info" title="Specific Configurations">
  Detailed environment guides for features like Stripe billing, Kumomta SMTP, workflows, and uploads are available under the respective backend/frontend setup files in the sidebar.
</Callout>

</Step>

<Step title="Start Reloop Services">

Reloop provides multiple options to start development servers. You can start all microservices together, run frontend or backend suites separately, or boot specific components individually.

<CodeGroup>
  <CodeBlock title="Option A: Start All (Standard)">
  ```bash
  # Concurrently starts all frontend & backend services via Turbo
  bun dev
  ```
  </CodeBlock>

  <CodeBlock title="Option B: Frontends Only">
  ```bash
  # Concurrently starts web app, user dashboard, admin dashboard, and docs
  bun frontend:dev
  ```
  </CodeBlock>

  <CodeBlock title="Option C: Backends Only">
  ```bash
  # Concurrently starts all backend microservice API instances
  bun backend:dev
  ```
  </CodeBlock>
</CodeGroup>

<Callout type="tip" title="Starting Individual Services">
  If you are only working on one service and want to save system resources, you can target it directly using Bun filters:
  - **Auth API**: `bun be:auth:dev`
  - **Dashboard Front**: `bun fe:dashboard:dev`
  - **Domain API**: `bun be:domain:dev`
</Callout>

</Step>
</Steps>

## Service URLs and Ports Reference

Once the services are running, they are available on the following local ports and URLs:

### Frontend Applications

| Application | URL | Port | Description |
| :--- | :--- | :--- | :--- |
| **Web App** | http://localhost:3000 | `3000` | Main public website and marketing pages |
| **Admin Dashboard** | http://localhost:3001 | `3001` | System administrator dashboard for user/system management |
| **User Dashboard** | http://localhost:3002 | `3002` | Main client app (workspaces, lists, campaigns) |
| **Public Docs** | http://localhost:3003 | `3003` | This developer/public documentation portal |
| **Dev Docs** | http://localhost:3004 | `3004` | Internal developer documentation reference site |

### Backend API Services

| Service | URL | Port | Description |
| :--- | :--- | :--- | :--- |
| **Auth API** | http://localhost:4001 | `4001` | User signup, signin, permissions, and Better Auth |
| **Domain API** | http://localhost:4002 | `4002` | Domain delegation, DKIM, and DNS verification service |
| **Audience API** | http://localhost:4003 | `4003` | Recipient groups, segmentation, and list managers |
| **Webhook API** | http://localhost:4004 | `4004` | Outgoing system notifications and HTTP POST triggers |
| **Mail API** | http://localhost:4005 | `4005` | Dynamic HTML generation and SMTP queuing |

## Quick Developer Cheat Sheet

Keep these core monorepo commands handy for routine tasks:

| Command | Action | Scope |
| :--- | :--- | :--- |
| `bun run check` | Run code quality checks, lints, and format checks | Full Monorepo |
| `bun db:push` | Synchronize current schema changes to PostgreSQL | Database |
| `bun db:seed` | Re-seed the local database with default data | Database |
| `bun docker:down` | Stop and tear down all docker containers | Infrastructure |
| `bun run --filter=<package-name> <script>` | Run a package script specifically | Target Package |
