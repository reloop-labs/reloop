# API Key Service

> Manages the lifecycle of developer API keys for the Reloop platform. It securely generates, hashes, stores, validates, and revokes API keys, enabling secure machine-to-machine interactions.

<Callout type="info" title="Prerequisite">
Make sure you've completed the [local setup guide](/setup) first.
</Callout>

---

## Quick Start

```bash
# One command to get started
cd apps/backend/api-key && cp env.example .env && bun i && bun dev
```

The service will be available at [http://localhost:8012/api/api-key](http://localhost:8012/api/api-key) or [https://local.reloop.sh/api/api-key](https://local.reloop.sh/api/api-key) 🎉

---

## Service Info

* **Location:** `/apps/backend/api-key`
* **Port:** `8012` (configurable)
* **Tech Stack:** Elysia.js, Better Auth API Key Plugin, PostgreSQL, Redis, NATS
* **Part of Monorepo:** Yes (run with filters or inside service dir)
* **API Base:** `/api/api-key`

---

## Environment Setup

Create `.env` file inside `/apps/backend/api-key`:

```bash
PORT=8012
NODE_ENV=development
PG_URL=postgresql://reloop:reloop123@localhost:5432/reloop
REDIS_URL=redis://:reloop123@localhost:6379
BASE_URL=https://local.reloop.sh
NATS_URL=nats://localhost:4222
```

| Variable | Required | Description |
| :--- | :--- | :--- |
| `PORT` | `YES` | Port the service listens on (defaults to `8012`). |
| `PG_URL` | `YES` | PostgreSQL connection string for querying keys. |
| `REDIS_URL` | `YES` | Redis URL for caching api-key validations. |
| `NATS_URL` | `YES` | NATS message broker URL for broadcasting api-key events. |
| `BASE_URL` | `YES` | Reloop platform base URL. |

## Development Commands

```bash
# Install dependencies
bun i

# Start dev server with hot reload
bun dev
# or from monorepo root
bun run be:api-key:dev
# or using turbo filter
bun run --filter=api-key dev

# Build for production
bun run build
# or from monorepo root
bun run be:api-key:build
```

## Architecture & Integration

- **Better Auth Integration**: Leveraging the `@better-auth/api-key` plugin to handle robust key schemas, security, and hashing.
- **Cache Layer**: Frequently verified API keys are cached in Redis to minimize PostgreSQL queries on critical request pathways.
- **Events Broker**: Publishes validation and key creation/revocation events to **NATS** under the `api-key.*` subjects.
- **Database Schema**: Utilizes `@reloop/db` schema with the `api_key` table, where keys are stored hashed.
