The **API Key Service** is an **ElysiaJS** microservice designed to handle the generation, hashing, storage, cryptographical validation, and revocation of external developer API keys. This enables secure machine-to-machine integrations with the Reloop platform.

<Callout type="info" title="Prerequisite First" variant="note">
  Before starting the API Key Service, make sure you've completed the base [Local Development Setup](/docs/setup) (installed Bun, configured the hosts file, and started the Docker container stack).
</Callout>

---

## Quick Start

Dependencies are handled globally at the root directory. You can start the API Key Service development server instantly:

<CodeGroup>
  <CodeBlock title="From Monorepo Root (Recommended)">
  ```bash
  # Start the dev server with hot reloading
  bun be:api-key:dev
  ```
  </CodeBlock>

  <CodeBlock title="From the Service Folder">
  ```bash
  cd apps/backend/api-key
  bun dev
  ```
  </CodeBlock>
</CodeGroup>

Once running, the API Key Service will listen locally on port `8012`. You can test it via Caddy at [https://local.reloop.sh/api/api-key](https://local.reloop.sh/api/api-key) 🎉

---

## Service Information

* **Directory Location:** `apps/backend/api-key/`
* **Local Listening Port:** `8012` (ElysiaJS gateway)
* **Unified Access Route:** [https://local.reloop.sh/api/api-key](https://local.reloop.sh/api/api-key)
* **Primary Tech Stack:** ElysiaJS, Better Auth API Key Plugin, PostgreSQL, Redis, NATS
* **Dependencies:** Relies on PostgreSQL (to store and query keys) and Redis (to cache validated keys for high-performance API routing).

## Environment Configuration

The API Key Service environment variables are defined in `apps/backend/api-key/.env`. If you ran `bun env:setup` at the root, your `.env` is already configured:

```bash
# Database Configuration
PG_URL=postgresql://reloop:reloop123@localhost:5432/reloop
REDIS_URL=redis://:reloop123@localhost:6379

# Server Gateway Configuration
PORT=8012
BASE_URL="https://local.reloop.sh"
NODE_ENV=development

# Event Bus Broker
NATS_URL=nats://localhost:4222
```

### Reference Table

| Variable | Required | Default Value | Description |
| :--- | :--- | :--- | :--- |
| `PG_URL` | **YES** | `postgresql://...` | PostgreSQL connection string. |
| `REDIS_URL` | **YES** | `redis://...` | Redis connection URL for key validation caching. |
| `PORT` | **YES** | `8012` | Local port number the Elysia app listens to on the host. |
| `BASE_URL` | **YES** | `https://local.reloop.sh` | Main application domain (used for cookie validations). |
| `NATS_URL` | **YES** | `nats://localhost:4222` | Connection URL for NATS event bus messaging. |
| `NODE_ENV` | **YES** | `development` | Active environment scope (`development` or `production`). |

## Architecture & Integration

* **Better Auth API Key Plugin**: Integrates `@better-auth/api-key` to manage secure hashing algorithms (SHA-256) and key formatting schemas.
* **Validation Cache Layer**: Frequently validated keys are cached in Redis to minimize relational DB lookups. Validation latency is kept under 5ms.
* **Broadcasting Events**: Publishes real-time key generation and revocation events to NATS under the `api-key.*` subject hierarchy (notifying the analytics and log tracking modules).
* **Database Models**: Integrates the database client from `@reloop/db`, referencing the Drizzle schemas inside the `api_key` tables. Keys are strictly hashed before persisting to PostgreSQL.
