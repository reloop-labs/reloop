The **Auth Service** is a high-performance **ElysiaJS** microservice that orchestrates user registrations, logins, organization structures, and session authorization across the platform using **Better Auth**.

<Callout type="info" title="Prerequisite First">
  Before setting up the Auth Service individually, ensure you have completed the base [Local Development Setup](/setup) (installed Bun, configured the hosts file, and started the Docker container suite).
</Callout>

---

## Quick Start

Since dependencies are managed globally at the monorepo root, you can boot the Auth Service development server instantly:

<CodeGroup>
  <CodeBlock title="From Monorepo Root (Recommended)">
  ```bash
  # Start the dev server with hot reloading
  bun be:auth:dev
  ```
  </CodeBlock>

  <CodeBlock title="From the Service Folder">
  ```bash
  cd apps/backend/auth
  bun dev
  ```
  </CodeBlock>
</CodeGroup>

Once running, the Auth Service API will be listening locally on port `8000`. You can test it via Caddy at [https://local.reloop.sh/api/auth](https://local.reloop.sh/api/auth) 🎉

---

## Service Information

* **Directory Location:** `apps/backend/auth/`
* **Local Listening Port:** `8000` (ElysiaJS gateway)
* **Unified Access Route:** [https://local.reloop.sh/api/auth](https://local.reloop.sh/api/auth)
* **Primary Tech Stack:** ElysiaJS, Better Auth, PostgreSQL, Redis, NATS
* **Dependencies:** Requires PostgreSQL (database) and Redis (caches & rate limits) to be healthy in Docker.

## Environment Configuration

The Auth Service reads its environment variables from `apps/backend/auth/.env`. If you ran `bun env:setup` at the root, your `.env` has already been populated with the default configurations:

```bash
# Database Configuration
PG_URL=postgresql://reloop:reloop123@localhost:5432/reloop
REDIS_URL=redis://:reloop123@localhost:6379

# Better Auth Configuration
BETTER_AUTH_SECRET=tENkVU4GrhckuRw4Bcfh93EWgXOFcszn
BASE_URL="https://local.reloop.sh"
NODE_ENV=development
PORT=8000
NODE_TLS_REJECT_UNAUTHORIZED=0

# Messaging Bus Broker
NATS_URL=nats://localhost:4222

# OAuth Credentials (Optional)
GOOGLE_CLIENT_ID=your-google-client-id
GOOGLE_CLIENT_SECRET=your-google-client-secret
GITHUB_CLIENT_ID=your-github-client-id
GITHUB_CLIENT_SECRET=your-github-client-secret

# Initial Self-Host Configuration
DEFAULT_OTP=888888   # Default pass code for first login
DISABLE_SIGNUP=false # Set to true to disable signups after creating your admin account
```

### Reference Table

| Variable | Required | Default Value | Description |
| :--- | :--- | :--- | :--- |
| `PG_URL` | **YES** | `postgresql://...` | PostgreSQL database connection string. |
| `REDIS_URL` | **YES** | `redis://...` | Redis cache and session management connection URL. |
| `BETTER_AUTH_SECRET` | **YES** | `string` | Encryption key for securing active user sessions. |
| `BASE_URL` | **YES** | `https://local.reloop.sh` | Main application domain (used for cookie setting). |
| `PORT` | **YES** | `8000` | Local port number the Elysia app listens to on the host. |
| `NATS_URL` | **YES** | `nats://localhost:4222` | Connection URL for NATS event broker messaging. |
| `DEFAULT_OTP` | **NO** | `888888` | Development OTP bypass for initial account setup. |
| `DISABLE_SIGNUP` | **NO** | `false` | Restricts new user signups when set to `true`. |

## Development Commands

All workspace operations should be executed from the **monorepo root directory** using Turborepo filters:

| Command | Action | Scope |
| :--- | :--- | :--- |
| `bun be:auth:dev` | Start the Auth dev server with hot reloading | Development |
| `bun run --filter=auth build` | Build the Auth service for production | Production |
| `bun run --filter=auth start` | Run the compiled production build locally | Production |
| `bun run --filter=auth check-types` | Verify TypeScript type-safety | Code Quality |
| `bun run --filter=auth auth:generate` | Regenerate the Drizzle DB auth schemas | Better Auth |

## Troubleshooting

### PostgreSQL / Redis Connection Issues
* **Symptom:** Auth server prints database connection timeouts or Redis connection failures.
* **Resolution:** Ensure the global Docker Compose containers are fully operational:
  ```bash
  # Check container status
  docker ps
  
  # Boot them up if stopped
  bun docker:up
  ```

### Key and Cookie Share Issues
* **Symptom:** User cannot log in, or session cookies are rejected across subpages.
* **Resolution:** 
  1. Confirm your hosts file maps `local.reloop.sh` correctly (see [hosts setup](/setup#step-2-configure-local-domain-hosts-file)).
  2. Ensure you are accessing the user dashboard via `https://local.reloop.sh/dashboard` instead of `http://localhost:3001` (browsers block secure cookie sharing across distinct localhost ports).
