The **Contacts Service** is an **ElysiaJS** microservice that manages subscriber profiles, static lists, custom properties, dynamic segmentation, and opt-out/unsubscribe logs. It forms the core database for recipient audience targeting within the Reloop platform.

<Callout type="info" title="Prerequisite First">
  Before starting the Contacts Service, make sure you've completed the base [Local Development Setup](/setup) (installed Bun, configured the hosts file, and started the Docker container stack).
</Callout>

---

## Quick Start

Dependencies are handled globally at the root directory. You can start the Contacts Service development server instantly:

<CodeGroup>
  <CodeBlock title="From Monorepo Root (Recommended)">
  ```bash
  # Start the dev server with hot reloading
  bun be:contacts:dev
  ```
  </CodeBlock>

  <CodeBlock title="From the Service Folder">
  ```bash
  cd apps/backend/contacts
  bun dev
  ```
  </CodeBlock>
</CodeGroup>

Once running, the Contacts Service will listen locally on port `8014`. You can query it via Caddy at [https://local.reloop.sh/api/contacts](https://local.reloop.sh/api/contacts) 🎉

---

## Service Information

* **Directory Location:** `apps/backend/contacts/`
* **Local Listening Port:** `8014` (configurable with `PORT` env variable)
* **Unified Access Route:** [https://local.reloop.sh/api/contacts](https://local.reloop.sh/api/contacts)
* **Primary Tech Stack:** ElysiaJS, PostgreSQL, Redis, NATS
* **Dependencies:** Relies on PostgreSQL (to store contact relational data) and Redis (to store segment cache and temporary list metadata).

## Environment Configuration

The Contacts Service environment variables are defined in `apps/backend/contacts/.env`. If you ran `bun env:setup` at the root, your `.env` is already configured:

```bash
# Database & Cache Configurations
PG_URL=postgresql://reloop:reloop123@localhost:5432/reloop
REDIS_URL=redis://:reloop123@localhost:6379

# Server Gateway Configuration
PORT=8014
BASE_URL="https://local.reloop.sh"
NODE_ENV=development
NODE_TLS_REJECT_UNAUTHORIZED=0

# Event Bus Broker
NATS_URL=nats://localhost:4222
```

### Reference Table

| Variable | Required | Default Value | Description |
| :--- | :--- | :--- | :--- |
| `PG_URL` | **YES** | `postgresql://...` | PostgreSQL database connection string. |
| `REDIS_URL` | **YES** | `redis://...` | Redis connection URL for segmentation cache queries. |
| `PORT` | **YES** | `8014` | Local port number the Elysia app listens to on the host. |
| `BASE_URL` | **YES** | `https://local.reloop.sh` | Main application domain (used for cookie validations). |
| `NATS_URL` | **YES** | `nats://localhost:4222` | Connection URL for NATS event bus messaging. |
| `NODE_ENV` | **YES** | `development` | Active environment scope (`development` or `production`). |

## Development Commands

All workspace operations should be executed from the **monorepo root directory** using Turborepo filters:

| Command | Action | Scope |
| :--- | :--- | :--- |
| `bun be:contacts:dev` | Start the Contacts dev server with hot reloading | Development |
| `bun run --filter=contacts build` | Compile the Contacts service for production | Production |
| `bun run --filter=contacts start` | Run the compiled production build locally | Production |
| `bun run --filter=contacts check-types` | Verify TypeScript type-safety | Code Quality |

## Service Capabilities Explained

* **Subscriber List Management**: Creating, updating, and grouping subscribers into static lists or dynamic query-based segments (filtering by traits like active state, country, or custom tag parameters).
* **Extensible Schema Attributes**: Allows users to define custom attribute fields (such as `first_name`, `company`, `last_purchase_date`) on a per-contact basis, mapping them correctly during bulk campaign compilation.
* **NATS Broadcast Streaming**: Fires broker notifications on list uploads, contact deletions, or subscription changes (opt-in/opt-out status) to automatically notify downstream workflow and email engines.
* **Database Models**: Interfaces with `@reloop/db` PostgreSQL tables, primarily manipulating metadata inside `contact`, `list`, `list_contact`, and `custom_field`.
