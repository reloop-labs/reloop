The **Email Service** is an **ElysiaJS** microservice responsible for dispatching platform transactional emails—such as organization invitations, password reset links, verification codes, and billing alerts—directly to Reloop's own platform users.

<Callout type="warning" title="Important Distinction">
  Do not confuse this with the **Mailing Service**!
  * **Email Service (`email`)**: Direct platform notification service that listens to system NATS topics to email Reloop customers.
  * **Mail Service (`mail`)**: High-throughput public API that allows Reloop customers to send campaigns to *their* audiences.
</Callout>

<Callout type="info" title="Prerequisite First">
  Before starting the Email Service, make sure you've completed the base [Local Development Setup](/setup) (installed Bun, configured the hosts file, and started the Docker container stack).
</Callout>

---

## Quick Start

Dependencies are handled globally at the root directory. You can start the Email Service development server instantly:

<CodeGroup>
  <CodeBlock title="From Monorepo Root (Recommended)">
  ```bash
  # Start the dev server with hot reloading
  bun be:email:dev
  ```
  </CodeBlock>

  <CodeBlock title="From the Service Folder">
  ```bash
  cd apps/backend/email
  bun dev
  ```
  </CodeBlock>
</CodeGroup>

Once running, the Email Service will listen locally on port `8022`. You can query it via Caddy at [https://local.reloop.sh/api/email](https://local.reloop.sh/api/email) 🎉

---

## Service Information

* **Directory Location:** `apps/backend/email/`
* **Local Listening Port:** `8022` (configurable with `EMAIL_PORT` env variable)
* **Unified Access Route:** [https://local.reloop.sh/api/email](https://local.reloop.sh/api/email)
* **Primary Tech Stack:** ElysiaJS, NATS (for event subscriptions), Redis
* **Dependencies:** Relies on Redis (for rate limiting system requests) and NATS (to subscribe to system trigger events).

## Environment Configuration

The Email Service environment variables are defined in `apps/backend/email/.env`. If you ran `bun env:setup` at the root, your `.env` is already configured:

```bash
# App Configuration
EMAIL_PORT=8022
NODE_ENV=development
BASE_URL="https://local.reloop.sh"

# Event Bus Broker
NATS_URL=nats://localhost:4222

# System Keys & Senders
RELOOP_API_KEY=your-system-reloop-api-key
RELOOP_SENDER_DOMAIN=local.reloop.sh
```

### Reference Table

| Variable | Required | Default Value | Description |
| :--- | :--- | :--- | :--- |
| `EMAIL_PORT` | **YES** | `8022` | Local port number the Elysia app listens to on the host. |
| `BASE_URL` | **YES** | `https://local.reloop.sh` | Main application domain (used for cookie validations). |
| `NATS_URL` | **YES** | `nats://localhost:4222` | Connection URL for NATS event bus messaging. |
| `RELOOP_API_KEY` | **YES** | `(empty)` | Internal API key used to authorize transactional mail delivery requests. |
| `RELOOP_SENDER_DOMAIN` | **YES** | `(empty)` | Base domain used in the "From" header of system transactional emails. |
| `NODE_ENV` | **YES** | `development` | Active environment scope (`development` or `production`). |

## NATS Event Subscriptions

The Email Service is strictly reactive. It listens to core subjects published by other microservices over the **NATS** broker to dispatch emails:

* **`auth.*`**: Listens for authentication events, sending magic links and verification codes to users signing in.
* **`api-key.*`**: Sends notifications when new API keys are generated or revoked.
* **`domain.*`**: Triggers warnings when domain DNS checks fail, or confirmation notes once verified.
* **`billing.*`**: Dispatches system emails alerting administrators of failed top-ups or depleted credit balances.
* **`organization.*`**: Handles invitation emails when users are invited to join an organization.
