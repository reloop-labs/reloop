The **Domain Service** is an **ElysiaJS** microservice that handles custom email domain mapping, DKIM keys generation, DNS records validation, and domain verification status tracking.

<Callout type="info" title="Prerequisite First">
  Before setting up the Domain Service, make sure you've completed the base [Local Development Setup](/setup) (installed Bun, configured the hosts file, and started the Docker container stack).
</Callout>

---

## Quick Start

Dependencies are handled globally at the root directory. You can start the Domain Service development server instantly:

<CodeGroup>
  <CodeBlock title="From Monorepo Root (Recommended)">
  ```bash
  # Start the dev server with hot reloading
  bun be:domain:dev
  ```
  </CodeBlock>

  <CodeBlock title="From the Service Folder">
  ```bash
  cd apps/backend/domain
  bun dev
  ```
  </CodeBlock>
</CodeGroup>

Once running, the Domain Service will listen locally on port `8011`. You can query it via Caddy at [https://local.reloop.sh/api/domain](https://local.reloop.sh/api/domain) 🎉

---

## Service Information

* **Directory Location:** `apps/backend/domain/`
* **Local Listening Port:** `8011` (configurable with `PORT` env variable)
* **Unified Access Route:** [https://local.reloop.sh/api/domain](https://local.reloop.sh/api/domain)
* **Primary Tech Stack:** ElysiaJS, PostgreSQL, Redis, NATS
* **Dependencies:** Relies on PostgreSQL (to store domain ownership records) and NATS (to broadcast verification updates).

## Environment Configuration

The Domain Service environment variables are defined in `apps/backend/domain/.env`. If you ran `bun env:setup` at the root, your `.env` is already configured:

```bash
# Database & Cache Configurations
PG_URL=postgresql://reloop:reloop123@localhost:5432/reloop
REDIS_URL=redis://:reloop123@localhost:6379

# Server Gateway Configuration
PORT=8011
BASE_URL="https://local.reloop.sh"
NODE_ENV=development
NODE_TLS_REJECT_UNAUTHORIZED=0

# Domain Verification Parameters
HOST_DOMAIN=reloop.sh
DKIM_SELECTOR=reloop

# Event Bus Broker
NATS_URL=nats://localhost:4222
```

### Reference Table

| Variable | Required | Default Value | Description |
| :--- | :--- | :--- | :--- |
| `PG_URL` | **YES** | `postgresql://...` | PostgreSQL database connection string. |
| `REDIS_URL` | **YES** | `redis://...` | Redis connection URL for temporary validation lookups. |
| `PORT` | **YES** | `8011` | Local port number the Elysia app listens to on the host. |
| `BASE_URL` | **YES** | `https://local.reloop.sh` | Main application domain (used for cookie validations). |
| `HOST_DOMAIN` | **YES** | `reloop.sh` | Base sender domain routing for test mails. |
| `DKIM_SELECTOR` | **YES** | `reloop` | The selector name used to query the active DKIM TXT record. |
| `NATS_URL` | **YES** | `nats://localhost:4222` | Connection URL for NATS event bus messaging. |
| `NODE_ENV` | **YES** | `development` | Active environment scope (`development` or `production`). |

## DNS Record Generation Standard

When a customer maps a domain inside Reloop, the service generates four core DNS authentication records.

### 1. MX Record (Mail Exchanger)
```text
Type:     MX
Name:     send.example.com
Value:    mail.reloop.sh
Priority: 10
```
Allows Reloop servers to intercept bounced messages or incoming contact replies.

### 2. SPF Record (Sender Policy Framework)
```text
Type:  TXT
Name:  send.example.com
Value: v=spf1 include:mail.reloop.sh -all
```
Explicitly authorizes Reloop servers (`mail.reloop.sh`) to send email on behalf of the customer's domain, dropping unauthorized senders (`-all`).

### 3. DKIM Record (DomainKeys Identified Mail)
```text
Type:  TXT
Name:  reloop._domainkey.send.example.com
Value: v=DKIM1; k=rsa; p=<public key>
```
Signs outbound headers with an RSA-2048 private key. The public key is published here to let receiving mailboxes cryptographically authenticate signatures.

### 4. DMARC Record (Domain-based Message Authentication)
```text
Type:  TXT
Name:  _dmarc.send.example.com
Value: v=DMARC1; p=none;
```
Standardizes delivery alignment standards. Initially set to monitoring mode (`p=none`) for smooth integration.
