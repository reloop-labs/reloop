## Overview

The Domain Service handles everything needed to send email from a custom domain: DNS record generation, domain verification, and ongoing status tracking. When a user adds their domain, this service creates the MX, SPF, DKIM, and DMARC records they need to configure, then verifies those records are live.

## Database schema

Schema lives in `packages/db/src/schema/domain.ts`. Two tables: `domain` and `domain_dns_record`.

### Enums

| Enum | Values |
|---|---|
| `domain_type` | `custom` · `subdomain` · `system` |
| `domain_status` | `start-verify` · `verifying` · `active` · `suspended` · `failed` |
| `dns_record_type` | `A` · `AAAA` · `CNAME` · `MX` · `TXT` |
| `dns_record_type_name` | `MX` · `SPF` · `DKIM` · `DMARC` |
| `tls_mode` | `opportunistic` · `enforced` |

**`domain_type`** — `custom` is a domain the user owns, `subdomain` is a subdomain of their domain, `system` is Reloop-managed.

**`domain_status`** — tracks the full verification lifecycle from `start-verify` through `active` or `failed`.

**`dns_record_type_name`** — semantic classification for email auth records. SPF, DKIM, and DMARC are all stored as `TXT` records under the hood.

**`tls_mode`** — `opportunistic` attempts TLS but falls back to plaintext; `enforced` requires TLS for all connections.

### Relationships

- **Organization ↔ Domain**: An organization can have multiple domains configured for email sending.
- **Domain ↔ DNS Record**: Each domain generates a set of DNS records (MX, SPF, DKIM, DMARC) for verification.
- **Direct Links**: Both tables carry `organizationId` and `userId` for simplified querying and clear audit trails.

## DNS records

When a domain is added, the service generates four records the user must add to their DNS provider. All records use `send.example.com` as the sending subdomain.

### MX

```
Type:     MX
Name:     send.example.com
Value:    mail.reloop.sh
Priority: 10
```

Routes incoming email (bounces, replies) to Reloop's mail servers.

### SPF

```
Type:  TXT
Name:  send.example.com
Value: v=spf1 include:mail.reloop.sh -all
```

Authorizes `mail.reloop.sh` to send on behalf of the domain. The `-all` means any other sender will fail.

### DKIM

```
Type:  TXT
Name:  reloop._domainkey.send.example.com
Value: v=DKIM1; k=rsa; p=<public key>
```

A 2048-bit RSA key pair is generated on domain creation. The private key is stored in `domain_dns_record.privateKey`; the public key is published here so receiving servers can verify the signature on outbound mail.

### DMARC

```
Type:  TXT
Name:  _dmarc.send.example.com
Value: v=DMARC1; p=none;
```

Sets the email authentication policy to monitor mode (`p=none`). No mail is rejected at this stage — useful while verifying alignment before moving to stricter policies.
