## Service Overview

Custom domain mapping, DKIM signature keys generation, SPF/DMARC/MX record lookups, and tracking subdomains (CNAME) verification.

| Property | Value |
| :--- | :--- |
| **Directory** | `apps/backend/domain` |
| **Port** | `8011` |
| **Local URL** | [https://local.reloop.sh/api/domain](https://local.reloop.sh/api/domain) |
| **Swagger UI** | [https://local.reloop.sh/api/domain/openapi](https://local.reloop.sh/api/domain/openapi) |
| **Stack** | `ElysiaJS` `PostgreSQL` `Redis` `NATS` `node:dns` |


## Quick Start

<Callout icon="union" variant="info">
Run the following command from the root of the monorepo:
</Callout>

```bash
bun be:domain:dev
```

The service starts with hot reloading on port `8011`.


## Environment Configuration

Variables live in `apps/backend/domain/.env`. Running `bun env:setup` from the root auto-populates this file.

```bash
# Databases
PG_URL=postgresql://reloop:reloop123@localhost:5432/reloop
REDIS_URL=redis://:reloop123@localhost:6379

# Server
PORT=8011
BASE_URL="https://local.reloop.sh"
NODE_ENV=development

# Verification Settings
HOST_DOMAIN=reloop.sh
DKIM_SELECTOR=reloop

# Event Bus
NATS_URL=nats://localhost:4222
```

## DNS Record Architecture & UI Sections

The DNS records are grouped and displayed on the UI in five distinct functional capability sections. The backend dynamically verifies each section depending on the user's toggle configuration.

### 1. Domain Verification
This is the mandatory baseline record required to verify domain ownership and establish email authenticity.

| Type | Default Name | Expected Value | TTL |
| :--- | :--- | :--- | :--- |
| `TXT` | `reloop._domainkey.send.example.com` | `v=DKIM1; k=rsa; p=<RSA-2048 Public Key>` | `Auto` |

* **DKIM (DomainKeys Identified Mail)**: Cryptographically signs outbound message headers using a secure private key generated by the microservice. The public key is published here to let receiving inbox providers verify that the message was truly sent from this domain.

---

### 2. Enable Sending
These records authorize Reloop servers to deliver emails on behalf of the customer's domain and set up the default return path routing.

| Type | Default Name | Expected Value | TTL | Priority |
| :--- | :--- | :--- | :--- | :--- |
| `TXT` | `send.example.com` | `v=spf1 include:reloop.sh -all` | `Auto` | — |
| `MX` | `send.example.com` | `reloop.sh` | `Auto` | `10` |

* **SPF (Sender Policy Framework)**: Whitelists the Reloop delivery IP pool/domain (`reloop.sh`) as a legitimate sender. Senders not explicitly included here are rejected (`-all`).
* **MX (Outbound Return Path)**: Binds the bounce/delivery status feedback loop to Reloop SMTP gateways to track outbound bounces and failures.

---

### 3. DMARC (Optional)
Specifies the alignment standard rules for how receiving servers should treat unauthenticated mails.

| Type | Default Name | Expected Value | TTL |
| :--- | :--- | :--- | :--- |
| `TXT` | `_dmarc.send.example.com` | `v=DMARC1; p=reject;` | `Auto` |

* **DMARC Record**: Instructs recipient mailboxes to reject (`p=reject`) any messages failing SPF or DKIM checks, ensuring maximum brand safety.

---

### 4. Enable Receiving
Allows Reloop inbound servers to capture incoming contact replies and handle bounce signals.

| Type | Default Name | Expected Value | TTL | Priority |
| :--- | :--- | :--- | :--- | :--- |
| `MX` | `inbound.send.example.com` | `reloop.sh` | `Auto` | `10` |

* **MX (Inbound Receiving)**: Directs incoming contact responses or replies targeting `inbound.send.example.com` directly back into Reloop's message router.

---

### 5. Enable Tracking
Configures secure custom tracking subdomains to sign link click metrics and open tracking pixel assets.

| Type | Default Name | Expected Value | TTL |
| :--- | :--- | :--- | :--- |
| `CNAME` | `tracking.send.example.com` | `reloop.sh` | `Auto` |

* **CNAME (Custom Branded Tracking)**: Rewrites click-redirection endpoints and open metrics pixels under your custom tracking subdomain to optimize delivery reputation.


## Dynamic Verification (NATS / BullMQ)

| Component | Logic |
| :--- | :--- |
| **DKIM Check** | Mandatory baseline verification — always queried. |
| **SPF & DMARC Checks** | Verified only when `isSendingEmailEnabled` is set to `true`. |
| **MX Inbound Check** | Verified only when `isReceivingEmailEnabled` is set to `true`. |
| **CNAME Tracking Check** | Verified only when click or open tracking is enabled. |
| **Auto-Pass Rules** | Bypassed capabilities automatically default their record success state to `true` to prevent blocking domain activation. |
