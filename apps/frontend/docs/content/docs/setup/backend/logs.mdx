The **Logs & Analytics Service** is an **ElysiaJS** microservice that acts as the platform's high-performance analytical engine. It consumes delivery events, tracking signals, and system audits to structure them into **ClickHouse** for fast, low-latency aggregations.

<Callout type="info" title="Prerequisite First">
  Before starting the Logs Service, make sure you have completed the base [Local Development Setup](/setup) and have ClickHouse running inside your Docker container stack (`bun docker:up`).
</Callout>

---

## Quick Start

Dependencies are handled globally at the root directory. You can start the Logs Service development server instantly:

<CodeGroup>
  <CodeBlock title="From Monorepo Root (Recommended)">
  ```bash
  # Start the dev server with hot reloading
  bun run --filter=logs dev
  ```
  </CodeBlock>

  <CodeBlock title="From the Service Folder">
  ```bash
  cd apps/backend/logs
  bun dev
  ```
  </CodeBlock>
</CodeGroup>

Once running, the Logs Service will listen locally on port `8016`. You can query it via Caddy at [https://local.reloop.sh/api/logs](https://local.reloop.sh/api/logs) 🎉

---

## Service Information

* **Directory Location:** `apps/backend/logs/`
* **Local Listening Port:** `8016` (configurable with `PORT` env variable)
* **Unified Access Route:** [https://local.reloop.sh/api/logs](https://local.reloop.sh/api/logs)
* **Primary Tech Stack:** ElysiaJS, ClickHouse, Redis, NATS
* **Dependencies:** Relies on ClickHouse (as the primary columnar analytical store) and NATS (to subscribe to real-time delivery and click event buses).

## Environment Configuration

The Logs Service environment variables are defined in `apps/backend/logs/.env`. If you ran `bun env:setup` at the root, your `.env` is already configured:

```bash
# Columnar Analytical DB Configurations
CLICKHOUSE_URL=http://localhost:8123
CLICKHOUSE_USER=default
CLICKHOUSE_PASSWORD=reloop123
CLICKHOUSE_DATABASE=reloop

# Cache Configurations
REDIS_URL=redis://:reloop123@localhost:6379

# Server Gateway Configuration
PORT=8016
BASE_URL="https://local.reloop.sh"
NODE_ENV=development

# Event Bus Broker
NATS_URL=nats://localhost:4222
```

### Reference Table

| Variable | Required | Default Value | Description |
| :--- | :--- | :--- | :--- |
| `CLICKHOUSE_URL` | **YES** | `http://localhost:8123` | ClickHouse server HTTP connection URL. |
| `CLICKHOUSE_USER` | **YES** | `default` | ClickHouse authenticated database user. |
| `CLICKHOUSE_PASSWORD`| **YES** | `reloop123` | ClickHouse authenticated user password. |
| `CLICKHOUSE_DATABASE`| **YES** | `reloop` | The active ClickHouse database schema target. |
| `REDIS_URL` | **YES** | `redis://...` | Redis connection URL for temporary log queues. |
| `PORT` | **YES** | `8016` | Local port number the Elysia app listens to on the host. |
| `BASE_URL` | **YES** | `https://local.reloop.sh` | Main application domain (used for cookie validations). |
| `NATS_URL` | **YES** | `nats://localhost:4222` | Connection URL for NATS event bus messaging. |
| `NODE_ENV` | **YES** | `development` | Active environment scope (`development` or `production`). |

## Development Commands

All workspace operations should be executed from the **monorepo root directory** using Turborepo filters:

| Command | Action | Scope |
| :--- | :--- | :--- |
| `bun run --filter=logs dev` | Start the Logs dev server with hot reloading | Development |

## ClickHouse Schema & Events Processing

* **Columnar Querying Architecture**: Built to handle billions of analytical rows, batching insertions from the event queues every 1-5 seconds to optimize disk writes.
* **Tracked Event Types**:
  * `sent`: Confirms that an outbound campaign job was generated.
  * `delivered`: Records MTA SMTP success handshakes.
  * `bounce`: Logs soft bounces (temporary failures) or hard bounces (invalid addresses).
  * `complaint`: Tracks user spam feedback loops.
  * `open`: Recorded when the 1px transparent tracking gif is requested from Caddy.
  * `click`: Fired when a customer interacts with signed tracking URLs redirection gateways.
* **Dashboard Aggregations**: Exposes optimized SQL aggregation endpoints queried by the customer dashboard to construct charts, tracking stats, bounce ratios, and delivery ledger logs.
