# Template Service

> Manages the creation, versioning, storage, and compilation of HTML and rich-text email templates. It compiles layouts with dynamic handlebars-style variables prior to sending.

<Callout type="info" title="Prerequisite">
Make sure you've completed the [local setup guide](/setup) first.
</Callout>

---

## Quick Start

```bash
# One command to get started
cd apps/backend/template && cp env.example .env && bun i && bun dev
```

The service will be available at [http://localhost:8019/api/template](http://localhost:8019/api/template) or [https://local.reloop.sh/api/template](https://local.reloop.sh/api/template) 🎉

---

## Service Info

* **Location:** `/apps/backend/template`
* **Port:** `8019` (configurable)
* **Tech Stack:** Elysia.js, PostgreSQL, Redis, NATS
* **Part of Monorepo:** Yes (run with filters or inside service dir)
* **API Base:** `/api/template`

---

## Environment Setup

Create `.env` file inside `/apps/backend/template`:

```bash
PORT=8019
NODE_ENV=development
PG_URL=postgresql://reloop:reloop123@localhost:5432/reloop
REDIS_URL=redis://:reloop123@localhost:6379
BASE_URL=https://local.reloop.sh
NATS_URL=nats://localhost:4222
```

| Variable | Required | Description |
| :--- | :--- | :--- |
| `PORT` | `YES` | Port the template server listens on (defaults to `8019`). |
| `PG_URL` | `YES` | PostgreSQL connection string for querying templates. |
| `REDIS_URL` | `YES` | Redis URL for temporal layout caching. |
| `NATS_URL` | `YES` | NATS message broker URL for broadcasting template change events. |

## Development Commands

```bash
# Install dependencies
bun i

# Start dev server with hot reload
bun dev
# or from monorepo root
bun run be:template:dev
# or using turbo filter
bun run --filter=template dev

# Build for production
bun run build
# or from monorepo root
bun run be:template:build
```

## Core Capabilities

- **Handlebars / Variable Compilation**: Compiles dynamic tokens (e.g. `{{ contact.first_name }}`, `{{ unsubscribe_link }}`) into final email HTML.
- **Template Versioning**: Manages draft vs. active states, allowing developers or marketers to edit templates without breaking live campaign pipelines.
- **Asset Integrations**: Interfaces with the `upload` service to pull in media URLs, and compiles responsive CSS inline layouts.
- **Database Schema**: Leverages PostgreSQL tables under `@reloop/db` schema, primarily `email_template` and `email_template_version`.
