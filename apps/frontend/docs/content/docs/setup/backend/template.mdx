The **Template Service** is an **ElysiaJS** microservice that manages the creation, versioning, storage, block editing, and high-performance compilation of HTML and rich-text email templates. It is responsible for compiling handlebars-style parameters prior to email dispatch.

<Callout type="info" title="Prerequisite First">
  Before starting the Template Service, make sure you've completed the base [Local Development Setup](/setup) (installed Bun, configured the hosts file, and started the Docker container stack).
</Callout>

---

## Quick Start

Dependencies are handled globally at the root directory. You can start the Template Service development server instantly:

<CodeGroup>
  <CodeBlock title="From Monorepo Root (Recommended)">
  ```bash
  # Start the dev server with hot reloading
  bun be:template:dev
  ```
  </CodeBlock>

  <CodeBlock title="From the Service Folder">
  ```bash
  cd apps/backend/template
  bun dev
  ```
  </CodeBlock>
</CodeGroup>

Once running, the Template Service will listen locally on port `8019`. You can query it via Caddy at [https://local.reloop.sh/api/template](https://local.reloop.sh/api/template) 🎉

---

## Service Information

* **Directory Location:** `apps/backend/template/`
* **Local Listening Port:** `8019` (configurable with `PORT` env variable)
* **Unified Access Route:** [https://local.reloop.sh/api/template](https://local.reloop.sh/api/template)
* **Primary Tech Stack:** ElysiaJS, PostgreSQL, Redis, NATS
* **Dependencies:** Relies on PostgreSQL (to store templates) and Redis (to cache compiled layout objects).

## Environment Configuration

The Template Service environment variables are defined in `apps/backend/template/.env`. If you ran `bun env:setup` at the root, your `.env` is already configured:

```bash
# Database & Cache Configurations
PG_URL=postgresql://reloop:reloop123@localhost:5432/reloop
REDIS_URL=redis://:reloop123@localhost:6379

# Server Gateway Configuration
PORT=8019
BASE_URL="https://local.reloop.sh"
NODE_ENV=development
NODE_TLS_REJECT_UNAUTHORIZED=0

# Event Bus Broker
NATS_URL=nats://localhost:4222
```

### Reference Table

| Variable | Required | Default Value | Description |
| :--- | :--- | :--- | :--- |
| `PG_URL` | **YES** | `postgresql://...` | PostgreSQL database connection string. |
| `REDIS_URL` | **YES** | `redis://...` | Redis connection URL for temporary layout caching. |
| `PORT` | **YES** | `8019` | Local port number the Elysia app listens to on the host. |
| `BASE_URL` | **YES** | `https://local.reloop.sh` | Main application domain (used for cookie validations). |
| `NATS_URL` | **YES** | `nats://localhost:4222` | Connection URL for NATS event bus messaging. |
| `NODE_ENV` | **YES** | `development` | Active environment scope (`development` or `production`). |

## Core Capabilities Explained

* **Variable Merging & Parsing**: Parses handlebars tokens (e.g. `{{ contact.first_name }}`) and dynamic organizational loops to construct the final HTML string.
* **Layout Versioning States**: Separates draft versions from active campaign layouts. Enables content creators to revise templates in Drizzle without mutating active campaign queues.
* **Asset Integration**: Integrates directly with the asset upload handlers, rendering S3-stored media URLs safely.
* **Relational Storage**: Integrates `@reloop/db` schema, primarily manipulating records inside the `email_template` and `email_template_version` tables.
