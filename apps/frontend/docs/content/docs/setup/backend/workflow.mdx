The **Workflow Automation Service** is an **ElysiaJS** microservice that coordinates, schedules, and executes multi-step marketing automation journeys (such as drip email campaigns, delay timers, segment shifts, and profile updates). It is powered by BullMQ and exposes an administrative Bull Board UI.

<Callout type="info" title="Prerequisite First">
  Before starting the Workflow Service, make sure you've completed the base [Local Development Setup](/setup) (installed Bun, configured the hosts file, and started the Docker container stack).
</Callout>

---

## Quick Start

Dependencies are handled globally at the root directory. You can start the Workflow Service development server instantly:

<CodeGroup>
  <CodeBlock title="From Monorepo Root (Recommended)">
  ```bash
  # Start the dev server with hot reloading
  bun be:workflow:dev
  ```
  </CodeBlock>

  <CodeBlock title="From the Service Folder">
  ```bash
  cd apps/backend/workflow
  bun dev
  ```
  </CodeBlock>
</CodeGroup>

Once running, the Workflow Service will listen locally on port `8017`. You can query it via Caddy at [https://local.reloop.sh/api/workflow](https://local.reloop.sh/api/workflow) 🎉

* The administrative Bull Board dashboard will be active at [https://local.reloop.sh/api/workflow/bull-board](https://local.reloop.sh/api/workflow/bull-board) 📊

## Service Information

* **Directory Location:** `apps/backend/workflow/`
* **Local Listening Port:** `8017` (configurable with `PORT` env variable)
* **Unified Access Route:** [https://local.reloop.sh/api/workflow](https://local.reloop.sh/api/workflow)
* **Primary Tech Stack:** ElysiaJS, BullMQ, Redis, PostgreSQL, NATS
* **Dependencies:** Relies on PostgreSQL (to query workflows and triggers) and Redis (to schedule BullMQ delayed jobs).

## Environment Configuration

The Workflow Service environment variables are defined in `apps/backend/workflow/.env`. If you ran `bun env:setup` at the root, your `.env` is already configured:

```bash
# Database & Cache Configurations
PG_URL=postgresql://reloop:reloop123@localhost:5432/reloop
REDIS_URL=redis://:reloop123@localhost:6379

# Server Gateway Configuration
PORT=8017
BASE_URL="https://local.reloop.sh"
NODE_ENV=development
NODE_TLS_REJECT_UNAUTHORIZED=0

# Event Bus Broker
NATS_URL=nats://localhost:4222
```

### Reference Table

| Variable | Required | Default Value | Description |
| :--- | :--- | :--- | :--- |
| `PG_URL` | **YES** | `postgresql://...` | PostgreSQL database connection string. |
| `REDIS_URL` | **YES** | `redis://...` | Redis connection URL utilized by BullMQ to hold delay state timers. |
| `PORT` | **YES** | `8017` | Local port number the Elysia app listens to on the host. |
| `BASE_URL` | **YES** | `https://local.reloop.sh` | Main application domain (used for cookie validations). |
| `NATS_URL` | **YES** | `nats://localhost:4222` | Connection URL for NATS event bus messaging. |
| `NODE_ENV` | **YES** | `development` | Active environment scope (`development` or `production`). |

## Development Commands

All workspace operations should be executed from the **monorepo root directory** using Turborepo filters:

| Command | Action | Scope |
| :--- | :--- | :--- |
| `bun be:workflow:dev` | Start the Workflow dev server with hot reloading | Development |

## Architecture & Operational Details

* **BullMQ Async Workers**: Executes workflow pipelines in the background. If a step requires actions (such as sending a newsletter or waiting for a delivery trigger), the worker splits and delegates.
* **Accurate Delay Scheduling**: Relies on Redis delayed queues to run precise time loops (e.g. *"Wait 72 hours before executing the follow-up email node"*), ensuring high horizontal scalability without CPU blocking.
* **Bull Board Administration**: Integrates **Bull Board** directly into Elysia, exposing it at `/api/workflow/bull-board`. Developers can inspect active, delayed, completed, or failed queue jobs, and trigger manual retries.
* **Event Broker Reactive Triggers**: Hooks directly into NATS streams to start customer journeys reactively based on platform updates (e.g. `"Trigger Welcome Workflow when contact.created event is received"`).
