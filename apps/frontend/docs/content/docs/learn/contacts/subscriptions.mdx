A **subscription** is the relationship between one contact and one [channel](/docs/learn/contacts/channels). Each subscription is either **opt_in** (receive mail for that channel) or **opt_out** (do not receive).

This page covers dashboard management, the **preference center**, and API enrollment.

## What is the preference center?

The **preference center** is a hosted Reloop page where a subscriber manages their own channel choices **without logging in**.

Instead of only offering "Unsubscribe from everything," you give contacts a link where they can:

- Turn **off** marketing but keep product updates
- Turn **off** one channel while staying subscribed to others
- **Unsubscribe from all** channels in one action

You generate a **signed link** for each contact and place it in email footers or account settings. The link expires after a set time for security.

<Callout type="info" title="Plain-language summary">
  **Preference center** = the public webpage where your subscriber picks which email types they want. **Subscription** = their yes/no choice for each channel.
</Callout>

## How subscriptions fit together

```
Contact
  └── enrolled in Channel "Product Updates"  → opt_in
  └── enrolled in Channel "Marketing"        → opt_out
  └── global status: subscribed
```

| Layer | Controls | Example |
| --- | --- | --- |
| Global `status` | All mail | `unsubscribed` stops everything |
| Channel subscription | One category | opt_out of Marketing only |
| [Suppression](/docs/learn/contacts/suppression) | Automatic | hard bounce blocks all sends |

## Dashboard: manage one contact's subscriptions

1. Open **Contacts** → click a contact.
2. Find the **Channels** section on the detail page.
3. Toggle each channel **on** (opt_in) or **off** (opt_out).
4. Changes apply to the next send that respects channel preferences.

When **adding a contact**, assign channels in the create form — each pick sets the initial subscription.

## Dashboard: preview the preference center

When you create or edit a **public** channel (**Contacts → Channels**), the editor shows a **Subscriber preview** — how that channel appears on the preference page.

Use it to check naming and descriptions before sending campaigns.

## Preference center flow (end to end)

### Step 1 — Create public channels

Only channels with `visibility: public` appear on the preference page. See [Channels](/docs/learn/contacts/channels).

### Step 2 — Generate a signed link

Your backend calls the generate endpoint with an API key:

```
GET /api/contacts/v1/preferences/generate?contact_id=cont_123456789
```

Response includes a URL. Embed it in templates:

```html
<a href="{{ preference_url }}">Manage email preferences</a>
```

### Step 3 — Contact opens the page

The contact clicks the link. Reloop loads their public channels and current opt-in state — no login required.

### Step 4 — Contact saves choices

Toggles call public endpoints (token in URL, no API key):

| Action | Method | Endpoint |
| --- | --- | --- |
| Load page data | `GET` | `/api/contacts/v1/preferences/data?token=…` |
| Toggle a channel | `POST` | `/api/contacts/v1/preferences/update` |
| Unsubscribe from all | `POST` | `/api/contacts/v1/preferences/unsubscribe-all` |

## Enroll contacts via API

### At contact create

```typescript
const { response, error } = await reloop.contacts.create({
  email: "user@example.com",
  channels: [
    { channelId: "ch_security", subscription: "opt_in" },
    { channelId: "ch_marketing", subscription: "opt_out" },
  ],
});
if (error) throw error;
```

### Add to a channel later

```bash
POST /api/contacts/channel/:channel_id
```

```json
{ "contact_id": "cont_123", "subscription": "opt_in" }
```

Or identify by email:

```json
{ "email": "user@example.com", "subscription": "opt_in" }
```

### Update subscription

```bash
PATCH /api/contacts/channel/:channel_id
```

```json
{ "contact_id": "cont_123", "subscription": "opt_out" }
```

## Best practices

1. **Use separate channels** for transactional vs. marketing mail.
2. **Default marketing to opt_out** where regulations require explicit consent.
3. **Link to the preference center** in every marketing footer — fewer spam complaints and less [suppression](/docs/learn/contacts/suppression).
4. **Keep security alerts on opt_in** with clear naming so contacts do not disable critical mail.
