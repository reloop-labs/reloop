---
title: Properties
description: Define custom contact fields for personalization, filtering, and segmentation.
---

**Properties** are custom fields on contacts. Define each property once for your workspace, then set a value per contact. Use them in email templates, API payloads, and the contact detail page.

Built-in fields (`email`, `firstName`, `lastName`, `status`) live on the contact record itself — not as properties.

Related: [Contact records](/docs/learn/contacts/contacts)

## Property schema

| Field | Type | Description |
| --- | --- | --- |
| `id` | string | Unique ID (e.g. `prop_abc123`) |
| `propertyName` | string | Key used in API and templates (snake_case) |
| `propertyType` | enum | `string` or `number` |
| `defaultValue` | string \| null | Fallback when contact has no value |
| `createdAt` / `updatedAt` | string | Timestamps |

<Callout type="tip" title="Naming">
  Use lowercase `snake_case`: `first_name`, `company_name`, `mrr`. Keys must match `^[a-z0-9_]+$`.
</Callout>

## Property types

| Type | Store | Example values |
| --- | --- | --- |
| `string` | Text | `"Acme Corp"`, `"pro"` |
| `number` | Numeric | `12`, `99.5` |

## Using properties in email templates

```html
<p>Hi {{ contact.first_name }},</p>
<p>Your plan: {{ contact.plan_type }}</p>
<p>Seats: {{ contact.seats }}</p>
```

If a contact has no value and the property defines `fallbackValue`, Reloop uses the fallback at send time.

## Dashboard

### Properties tab

**Path:** Dashboard → **Contacts** → **Properties**

Lists every custom field in the workspace.

### Create a property

1. Click **Add Property**.
2. **Name** — e.g. `company_name` (becomes the merge key).
3. **Type** — String or Number.
4. **Fallback value** (optional) — e.g. `Unknown` or `0`.
5. Save.

### Set values on contacts

**Contact detail page** → **Custom Properties** section → edit each field.

Values can also be set when creating/updating via API. CSV import will support property columns when dashboard import launches — see [Migration guide](/docs/learn/contacts/migration-guide).

## API reference summary

| Operation | Method | Endpoint |
| --- | --- | --- |
| Create | `POST` | `/api/contacts/v1/properties/create` |
| List | `GET` | `/api/contacts/v1/properties/list` |
| Update | `PATCH` | `/api/contacts/v1/properties/:property_id` |
| Delete | `DELETE` | `/api/contacts/v1/properties/:property_id` |

Property **values** are set on the contact (`PATCH /api/contacts/:id`), not on the property definition.

## SDK examples

### Create a property

<CodeGroup>
```typescript Node.js SDK
const { response, error } = await reloop.contacts.createProperty({
  name: "company_name",
  type: "string",
  fallbackValue: "Unknown",
});

if (error) throw error;
console.log(response.id, response.propertyName);
```

```json POST /api/contacts/v1/properties/create
{
  "name": "company_name",
  "type": "string",
  "fallbackValue": "Unknown"
}
```
</CodeGroup>

### List properties

```typescript
const { response, error } = await reloop.contacts.listProperties({
  page: 1,
  limit: 100,
  search: "company",
  type: "string",
});
if (error) throw error;
```

### Update property definition (fallback / name)

```typescript
const { error } = await reloop.contacts.updateProperty("prop_123", {
  fallbackValue: "N/A",
});
if (error) throw error;
```

### Set values on a contact

```typescript
const { error } = await reloop.contacts.update("cont_123", {
  properties: {
    company_name: "Reloop",
    seats: 5,
  },
});
if (error) throw error;
```

### Set values at create time

```typescript
const { response, error } = await reloop.contacts.create({
  email: "user@example.com",
  properties: {
    company_name: "Acme",
    plan_type: "enterprise",
  },
});
if (error) throw error;
```

<Callout type="warning" title="Deleting a property">
  Deleting a definition removes the schema from the workspace. Values on contacts may no longer display until the property is re-created.
</Callout>
