The [Model Context Protocol](https://modelcontextprotocol.io) (MCP) is an open standard that lets AI assistants call external tools. The Reloop MCP server connects your assistant to your Reloop organization, so you can send email, manage contacts, check deliverability, and more by describing what you want in plain language.

Reloop runs a hosted MCP server for you. Add one URL to your client, sign in with your Reloop account, and you're done. There's no API key to copy and nothing to install.

| Setting | Value |
|---|---|
| **Server URL** | `https://reloop.sh/mcp` |
| **Transport** | Streamable HTTP |
| **Authentication** | Sign in with Reloop (OAuth) |

<Tip>
The [MCP page in your dashboard](https://reloop.sh/dashboard/integrations/mcp) has setup steps, one-click install buttons, and copyable config for each client.
</Tip>

## What you can do

The MCP server is built to do everything you can do in the Reloop dashboard:

- **Emails**: Send transactional email with HTML or plain text, CC/BCC, reply-to, tags, templates, and scheduled delivery. Check what you sent and its delivery status.
- **Contacts**: Look up, create, update, unsubscribe, and delete contacts. Manage custom properties, groups, and channel subscriptions.
- **Campaigns**: Draft, schedule, and send campaigns to your audience.
- **Templates**: Create and edit email templates and reuse them when sending.
- **Automation**: Build flows such as a welcome series that runs when someone signs up.
- **Inbox**: Read inbound email and attachments on your receiving domains.
- **Metrics & logs**: Inspect email logs, bounces, and engagement, and ask why a number changed.
- **Domains**: Add sending domains, check DNS records, and verify them.
- **Webhooks & API keys**: Create and manage webhooks for email events, and manage API keys.

See [example prompts](/docs/integrations/ai-tools/mcp-prompts) for ideas.

<Warning>
Sending email is real and can't be undone. Most clients ask you to approve each tool call; read the sender, recipients, and content before you approve a send or a delete.
</Warning>

## How sign-in works

The hosted server is an OAuth protected resource. You don't need an API key.

1. Your client connects to `https://reloop.sh/mcp` and gets a `401` with a `WWW-Authenticate` challenge.
2. It reads `https://reloop.sh/.well-known/oauth-protected-resource/mcp` to find Reloop's authorization server, and registers itself automatically.
3. Your browser opens the Reloop sign-in page. You sign in, pick the organization the client can access, and approve.
4. The client sends the access token as `Authorization: Bearer <token>` on every request.

Tokens are short-lived, scoped to the MCP server, and tied to the organization you approved. Reloop checks every call against your permissions, so the assistant can only do what your account can do.

### Choosing an organization

If you belong to several organizations, you pick one on the consent screen. To switch, sign in again from your client and pick a different one. Clients that support custom headers can also send an `x-organization-id` header to select an organization per request.

## Local server (stdio)

Use the local server when your client can't connect to a remote URL, or when you prefer an API key over signing in. Your client starts `reloop-mcp` as a child process and talks to it over stdin/stdout.

You'll need Node.js 20 or later (for `npx`) and a [Reloop API key](https://reloop.sh/dashboard/api-keys). Replace `rl_prod_your_api_key` with your key.

## Self-hosted Reloop

If you run your own Reloop instance, set `RELOOP_BASE_URL` to its origin. Nothing is tied to `reloop.sh` beyond the default.

For the hosted-style setup, your instance serves the MCP endpoint at `https://<your-domain>/mcp` and every remote setup above works with that URL in place of `https://reloop.sh/mcp`.

For the local server, add `RELOOP_BASE_URL` next to your key:

```json
{
  "mcpServers": {
    "reloop": {
      "command": "npx",
      "args": ["-y", "reloop-mcp"],
      "env": {
        "RELOOP_API_KEY": "rl_prod_your_api_key",
        "RELOOP_BASE_URL": "https://mail.example.com"
      }
    }
  }
}
```

## Run the HTTP server yourself

You can run the Streamable HTTP server on your own infrastructure. It's stateless: there are no sessions, so you can run several instances behind any load balancer.

```bash
bunx reloop-mcp --transport http --host 0.0.0.0 --port 3000
```

The standalone HTTP server needs [Bun](https://bun.sh). On Node.js, use the Docker image instead:

```bash
docker build -t reloop/mcp .
docker run --rm -p 3000:3000 -e RELOOP_BASE_URL=https://mail.example.com reloop/mcp
```

Clients connect to `http://<host>:3000/mcp` and authenticate on every request with one of:

- An OAuth access token: `Authorization: Bearer <token>` (recommended; clients get this by signing in)
- A Reloop API key: `Authorization: Bearer rl_prod_...` or `x-api-key: rl_prod_...`

`RELOOP_API_KEY` is not used by the HTTP transport. For example, to connect Claude Code with an API key:

```bash
claude mcp add --transport http reloop http://127.0.0.1:3000/mcp \
  --header "Authorization: Bearer rl_prod_your_api_key"
```

Check that the server is up:

```bash
curl -s http://127.0.0.1:3000/mcp/healthz
```

```json
{ "status": "ok", "name": "reloop", "version": "0.1.0" }
```

`GET /healthz` returns the same response.

## Options

**CLI flags**

| Flag | Default | Description |
|---|---|---|
| `--transport <stdio\|http>` | `stdio` | Transport to serve |
| `--host <hostname>` | `127.0.0.1` | HTTP bind hostname |
| `--port <number>` | `3000` | HTTP bind port |
| `--base-url <url>` | `https://reloop.sh` | Origin of the Reloop instance |
| `--version` | | Print the version and exit |
| `--help` | | Print help and exit |

**Environment variables**

| Variable | Default | Description |
|---|---|---|
| `RELOOP_API_KEY` | | Reloop API key. Required for stdio, ignored by HTTP |
| `RELOOP_BASE_URL` | `https://reloop.sh` | Origin of the Reloop instance |
| `RELOOP_MCP_RESOURCE` | `<base>/mcp` | Canonical MCP resource identifier. Must match the auth server's `MCP_RESOURCE` |
| `RELOOP_AUTH_ISSUER` | `<base>/api/auth/v1` | OAuth issuer advertised in the protected resource metadata |
| `RELOOP_TIMEOUT_MS` | `30000` | Per-request timeout to Reloop, from 1000 to 600000 |
| `HOST` | `127.0.0.1` | HTTP bind hostname |
| `PORT` | `3000` | HTTP bind port |
| `MCP_ALLOWED_HOSTS` | `*` | Comma-separated `Host` header allowlist. `*` or unset accepts any host |
| `MCP_ALLOWED_ORIGINS` | loopback origins | Comma-separated `Origin` header allowlist |
| `LOG_LEVEL` | `info` | `debug`, `info`, `warn`, `error`, or `silent` |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | unset | OTLP/HTTP endpoint (for example SigNoz). When set, every log line is also exported there |
| `OTEL_EXPORTER_OTLP_HEADERS` | unset | Headers for the OTLP endpoint as `key=value,key2=value2`, for example `signoz-ingestion-key=<key>` |

Even with `MCP_ALLOWED_HOSTS` unset, every request still needs an OAuth token or API key. Set it to restrict which hostnames the server answers on.

## Security

- Credentials are per request. The server forwards the caller's token or key to Reloop and never stores, caches, or shares it.
- API keys and tokens are redacted from logs, and email content is never logged.
- `Host` and `Origin` headers are validated to block DNS-rebinding attacks from a browser.
- `RELOOP_BASE_URL` is server configuration, never a tool parameter, so a model can't redirect traffic to another host.
- Tools that send email or delete data are marked destructive, so clients can ask you to confirm before they run.

## Local development

The server's source is at [github.com/reloop-labs/reloop-mcp](https://github.com/reloop-labs/reloop-mcp).

```bash
git clone https://github.com/reloop-labs/reloop-mcp.git
cd reloop-mcp
bun install
bun run dev:stdio   # stdio transport
bun run dev:http    # HTTP transport on http://127.0.0.1:3000/mcp, reloads on change
bun run build       # builds dist/cli.js
```

To point a stdio client at your local build, replace `npx -y reloop-mcp` with `node`:

```json
{
  "mcpServers": {
    "reloop": {
      "command": "node",
      "args": ["ABSOLUTE_PATH_TO_PROJECT/dist/cli.js"],
      "env": {
        "RELOOP_API_KEY": "rl_prod_your_api_key"
      }
    }
  }
}
```

Before opening a pull request, run `bun run lint`, `bun run typecheck`, and `bun test`.

## Test with MCP Inspector

[MCP Inspector](https://github.com/modelcontextprotocol/inspector) is a browser UI for calling MCP tools by hand.

### Stdio

From the `reloop-mcp` folder:

```bash
npx @modelcontextprotocol/inspector -e RELOOP_API_KEY=rl_prod_your_api_key bun src/cli.ts
```

Inspector opens in your browser with the server already configured. Click **Connect**, then **List Tools**.

### HTTP

1. Start the server:

    ```bash
    bun run dev:http
    ```

2. Start Inspector:

    ```bash
    npx @modelcontextprotocol/inspector
    ```

3. In the browser, choose **Streamable HTTP** and set the URL to `http://127.0.0.1:3000/mcp`.
4. Add a header `Authorization: Bearer rl_prod_your_api_key` and turn it on.
5. Click **Connect**, then **List Tools**.

To test against the hosted server, use `https://reloop.sh/mcp` without a header. Inspector walks you through the OAuth sign-in.

## Troubleshooting

<AccordionGroup>
  <Accordion title="My client says it can't authenticate or keeps asking me to sign in">
    Remove the saved sign-in from your client and authenticate again. Each client page above has the exact steps. If you're on a self-hosted instance, check that `RELOOP_MCP_RESOURCE` matches the auth server's `MCP_RESOURCE`.
  </Accordion>
  <Accordion title="Tools act on the wrong organization">
    Sign in again and pick the right organization on the consent screen, or send an `x-organization-id` header if your client supports custom headers. With an API key, create the key in the organization you want.
  </Accordion>
  <Accordion title="Sending fails with not_found or validation_error">
    The `from` address must use a sending domain that's verified in your organization. Ask your assistant to list your domains, or check [Domains](https://reloop.sh/dashboard/domain).
  </Accordion>
  <Accordion title="The local server exits with an error about RELOOP_API_KEY">
    The stdio transport needs `RELOOP_API_KEY`, and the key has to look like a Reloop key (for example `rl_prod_...`). Copy it again from the [API keys page](https://reloop.sh/dashboard/api-keys).
  </Accordion>
  <Accordion title="I get malformed_response errors">
    The server reached something that isn't a Reloop API, which usually means `RELOOP_BASE_URL` is wrong. Set it to the origin of your instance, without a path.
  </Accordion>
  <Accordion title="Calls time out">
    Retry reads. Don't blindly retry a send: the first one may have gone out. Check your email logs first. You can raise `RELOOP_TIMEOUT_MS` if you run the server yourself.
  </Accordion>
</AccordionGroup>
