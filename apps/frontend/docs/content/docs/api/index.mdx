Welcome to the Reloop API Reference. The Reloop API is built on **REST** principles. We enforce HTTPS in every request to improve data security, integrity, and privacy.

## Authentication

To authenticate, you need to add an `x-api-key` header with your API key:

```bash
curl -X GET "https://api.reloop.sh/api/domain/v1/list" \
  -H "x-api-key: rl_YOUR_API_KEY"
```

You can generate API keys from the [Reloop Dashboard](https://reloop.sh/dashboard/api-keys). Each API key is scoped to an organization and can be rotated or revoked at any time.

| Header | Value | Required |
|--------|-------|----------|
| `x-api-key` | Your Reloop API key (starts with `rl_prod_`) | Yes |
| `Content-Type` | `application/json` | For POST/PUT/PATCH requests |

## Response Codes

The API uses standard HTTP status codes to indicate success or failure:

| Code | Description |
|------|-------------|
| `200` | OK — Request succeeded |
| `201` | Created — Resource was created |
| `400` | Bad Request — Invalid parameters |
| `401` | Unauthorized — Missing or invalid API key |
| `403` | Forbidden — Not allowed to access this resource |
| `404` | Not Found — Resource doesn't exist |
| `409` | Conflict — Resource already exists |
| `429` | Too Many Requests — Rate limit exceeded |
| `500` | Internal Server Error |

## Rate Limits

The API enforces rate limits to ensure fair usage. If you exceed the limit, you'll receive a `429` response. 

Rate limits are applied per **organization**.

### Rate Limit Headers

Every response from the Reloop API includes headers indicating your current rate limit status:

| Header | Description |
|--------|-------------|
| `X-RateLimit-Limit` | The maximum number of requests allowed within the rate limit window. |
| `X-RateLimit-Remaining` | The number of requests remaining in the current window. |
| `X-RateLimit-Window` | The size of the rate limit window in seconds (returned by management endpoints). |
| `X-RateLimit-Reset` | The Unix epoch timestamp (in seconds) when the rate limit resets (returned by email sending endpoints). |
| `Retry-After` | The number of seconds you must wait before making another request (returned with `429` status codes). |

## Content Type

All request and response bodies are encoded as JSON. Make sure to set the `Content-Type: application/json` header for requests with a body.

## Errors

All error responses follow a consistent format:

```json
{
  "message": "A human-readable description of the error",
  "why": "Detailed explanation of why the error occurred",
  "fix": "Suggested steps to resolve the issue",
  "link": "https://reloop.sh/docs/api/errors"
}
```
