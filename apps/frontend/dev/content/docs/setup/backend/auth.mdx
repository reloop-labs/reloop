# Authentication Service

> Powers Reloop's user authentication, authorization, and session management. This Elysia.js service provides secure OAuth flows, JWT token handling, and user management for the entire Reloop platform.

<Callout type="info" title="Prerequisite">
Make sure you've completed the [local setup guide](/setup) first (clone repo, install Bun, and set up dependencies).
</Callout>

## Quick Start

```bash
# One command to get started
cd apps/backend/auth && cp env.example .env && bun i && bun dev
```

The service will be available at [http://localhost:8000/api/auth](http://localhost:8000/api/auth) 🎉

---

## Service Info

* **Location:** `/apps/backend/auth`
* **Port:** `8000` (hardcoded)
* **Tech Stack:** Elysia.js, Better Auth, PostgreSQL, Redis
* **Part of Monorepo:** Yes (run with filters or inside service dir)
* **API Base:** `/api/auth`

---

## Environment Setup

Create `.env` file:

```bash
# Database Configuration
PG_URL=postgresql://user:password@localhost:5432/auth_db

# Better Auth Configuration
BETTER_AUTH_SECRET=your-super-secret-key-here-make-it-long-and-random

# Google OAuth (Optional)
GOOGLE_CLIENT_ID=your-google-client-id
GOOGLE_CLIENT_SECRET=your-google-client-secret

# GitHub OAuth (Optional)
GITHUB_CLIENT_ID=your-github-client-id
GITHUB_CLIENT_SECRET=your-github-client-secret

# Server Configuration
NODE_ENV=development
HOSTNAME=0.0.0.0
```

| Variable                | Required | Description                                    |
| ----------------------- | -------- | ---------------------------------------------- |
| `PG_URL`                | `YES`       | PostgreSQL connection string for user data     |
| `BETTER_AUTH_SECRET`    | `YES`        | Secret key for JWT tokens and encryption      |
| `GOOGLE_CLIENT_ID`      | `NO`        | Google OAuth client ID for Google sign-in     |
| `GOOGLE_CLIENT_SECRET`  | `NO`        | Google OAuth client secret                    |
| `GITHUB_CLIENT_ID`      | `NO`        | GitHub OAuth client ID for GitHub sign-in     |
| `GITHUB_CLIENT_SECRET`  | `NO`        | GitHub OAuth client secret                    |
| `HOSTNAME`              | `NO`        | Server hostname (defaults to 0.0.0.0)        |

## Development Commands

```bash
# Install dependencies
bun i

# Start dev server with hot reload
bun dev
# or from monorepo root with filter
bun run --filter=auth dev

# Build for production
bun run build
# or from monorepo root
bun run --filter=auth build

# Start production server locally
bun run start
# or from monorepo root
bun run --filter=auth start

# Type checking
bun run check-types

# Database operations
bun run db:push      # Push schema changes to DB
bun run db:studio    # Open Drizzle Studio
bun run db:generate  # Generate migrations
bun run db:migrate   # Run migrations

# Auth schema generation
bun run auth:generate # Generate Better Auth schema
```

## Docker Development

### Using Docker Compose (Recommended)

```bash
cd apps/backend/auth
docker-compose up --build
```

This starts:
- PostgreSQL database on port 5432
- Auth service on port 8000

### Direct Docker

```bash
# Build image
docker build -f apps/backend/auth/Dockerfile -t auth-service .

# Run container
docker run -p 8000:8000 \
  -e PG_URL="postgresql://user:password@host:5432/db" \
  -e BETTER_AUTH_SECRET="your-secret-key" \
  auth-service
```

## Troubleshooting

### Database Connection Issues
**Can't connect to PostgreSQL?**
```bash
# Check if PostgreSQL is running
docker ps | grep postgres

# Verify connection string format
PG_URL=postgresql://username:password@host:port/database_name

# Test connection manually
psql "postgresql://username:password@localhost:5432/auth_db"
```

### Port Issues
**Port already in use?**
```bash
# Check what's using the port
lsof -i :8000

# Kill the process (replace PID)
kill -9 <PID>

# Port is hardcoded to 8000
```

### Build/Install Issues
**Bun install fails?**
```bash
# Clear cache and reinstall
rm -rf ~/.bun/install/cache
rm -rf node_modules
bun i

# Check Bun version
bun --version
```

### Auth Secret Issues
**Invalid auth secret?**
```bash
# Generate a new secure secret
openssl rand -base64 32

# Update .env file
BETTER_AUTH_SECRET=your-new-secret-here
```

## Notes

* Commands can be run inside this directory or from the root using filters
