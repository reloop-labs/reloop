**Listmonk and Reloop are both open source and both self-hostable, but they sit at different layers.** Listmonk is a newsletter and mailing list manager: it stores subscribers, builds campaigns and hands each message to an SMTP server you provide. Reloop is the email infrastructure itself: **it runs its own MTA, sends transactional and campaign mail, runs event-triggered automations, and receives mail into inboxes.** That's why many teams don't pick one: they point Listmonk at Reloop's SMTP.

We build Reloop, so weigh this accordingly. Every Listmonk fact below comes from [its GitHub repository](https://github.com/knadh/listmonk) and [documentation](https://listmonk.app/docs/), and where Listmonk is the better pick, we say so.

## Different layers of the stack

The most useful way to understand the comparison is to look at what happens when you hit "send".

**With Listmonk**, the app renders your campaign, queues it, and delivers every message over SMTP to a provider you configure: Amazon SES, Postmark, your own Postfix, or anything else. Listmonk's homepage lists "multi-SMTP e-mail queues" and "throughput and sliding window rate limiting", so you can spread sends across several relays and throttle them. But IP reputation, DKIM signing and the actual delivery to Gmail or Outlook belong to whoever runs that SMTP server.

**With Reloop**, the same stack does both jobs. The API, campaigns and automations sit on top of a KumoMTA delivery pipeline with per-domain throttling and automatic pauses when bounce or complaint rates spike. If you self-host Reloop, you own that MTA. If you use Reloop Cloud, we run it.

So "Reloop vs Listmonk" is partly "Reloop vs Listmonk plus SES". Keep that in mind when you compare cost and effort.

## Newsletters and campaigns

This is Listmonk's home turf, and it's very good at it.

- **Lists with single and double opt-in**, scaling to millions of subscribers.
- **SQL segmentation.** You query subscribers with SQL expressions, which is extremely flexible if your team is comfortable with SQL.
- **Editors.** A visual drag-and-drop builder, WYSIWYG, Markdown, HTML and plain text.
- **Templates in Go's templating language**, with logic and 100+ functions.
- **Built-in analytics** for campaign performance, bounces and top links.
- **Media library** with S3-compatible storage, i18n, and OIDC single sign-on with roles.

Reloop's campaigns cover the same ground in a different shape: contacts with custom properties, groups, subscription channels so people can opt out of one kind of mail without leaving everything, and scheduled broadcasts. Segmentation uses properties and groups rather than raw SQL.

If your main job is a newsletter and you love SQL, Listmonk will feel at home.

## Transactional email

Both can send one-off messages from your app, but they approach it differently.

**Listmonk** has a transactional endpoint that renders a stored template for a recipient:

```bash
curl -u "api_user:token" -X POST https://listmonk.example.com/api/tx \
  -H "Content-Type: application/json" \
  -d '{
    "subscriber_email": "user@example.com",
    "template_id": 3,
    "subscriber_mode": "fallback",
    "data": { "order_id": "1234" }
  }'
```

The template reads that data with `{{ .Tx.Data.order_id }}`. By default the recipient must already exist as a subscriber; `fallback` and `external` modes let you send to addresses that aren't in the database.

**Reloop** treats transactional mail as the main path, with an SDK and raw HTML or stored templates:

```typescript
import { Reloop } from "reloop-email";

const reloop = new Reloop({ apiKey: process.env.RELOOP_API_KEY! });

const { response, emailError } = await reloop.mail.send({
  from: "Acme <orders@mail.acme.com>",
  to: "user@example.com",
  subject: "Your order #1234",
  html: "<p>Thanks for your order.</p>",
});
```

On top of that you get per-message logs, delivery and bounce events, signed webhooks (`Reloop-Signature`, HMAC-SHA256), idempotency keys and scheduled sends. Stored templates use triple braces: `{{{order_id}}}`.

## Automations

Listmonk is intentionally a newsletter tool and doesn't ship drip sequences or event-triggered workflows. Teams that need them usually glue Listmonk's transactional API to an external workflow tool such as n8n.

Reloop has automations built in. You track an event from your app, and every active automation listening for it starts for that contact:

```typescript
const { automationError } = await reloop.automations.start({
  event: "user.signed_up",
  email: user.email,
  firstName: user.name,
  properties: { plan: user.plan },
});
```

Automations support delays, conditions and email steps. Our [welcome sequence guide](/blog/welcome-email-sequences-that-convert) builds a four-email onboarding flow this way.

## Receiving email

Listmonk is one-way. It sends mail and processes bounces, but it doesn't give you inboxes.

Reloop receives mail on your domains into **mailboxes**: messages are stored, threaded, spam-scored with Rspamd, and available over the API, the [MCP server](/docs/integrations/ai-tools/mcp-server) and IMAP. You can reply in-thread with one call. That covers "reply to this email" flows, support inboxes, and [AI agents that read and answer email](/blog/build-ai-agent-sends-emails).

## Bounces and deliverability

**Listmonk** processes bounces in two ways: by scanning a dedicated bounce mailbox over POP3, or by accepting webhooks. It understands webhooks from Amazon SES, Azure Communication Services, SendGrid, Postmark, Forward Email and Lettermint, plus a generic `/webhooks/bounce` endpoint. You then choose what happens at each threshold (none, blocklist or delete). Deliverability itself depends on your SMTP provider.

**Reloop** handles bounces, complaints and suppression inside the MTA, so there's nothing to wire up. One suppression list covers transactional mail, campaigns and automations. Free [domain reputation](/tools/domain-reputation-checker), [blocklist](/tools/blocklist-checker) and [auth](/tools/auth-checker) checkers help before you send.

## Licensing

Listmonk is **AGPLv3**. You can self-host and modify it freely, but if you offer a modified version to users over a network, the AGPL requires you to share those changes.

Reloop is **Apache 2.0**, a permissive license without that requirement. For most self-hosters neither license matters. It matters if you plan to embed or resell the software.

## Where Listmonk is the better choice

- **You only need newsletters.** Listmonk does that one job extremely well, with a mature UI and editors.
- **You want the smallest possible footprint.** A single Go binary and Postgres, running large campaigns in tens of megabytes of RAM.
- **Your team thinks in SQL.** Segmenting with SQL expressions is hard to beat for flexibility.
- **You already have a sending provider** you're happy with, such as SES at a contracted rate.

If you want to compare more newsletter tools, hosted or self-hosted, see the [best Listmonk alternatives](/blog/best-listmonk-alternatives).

## Where Reloop is the better choice

- **You send transactional mail and campaigns from one product**, with one suppression list and one set of logs.
- **You need automations** triggered by events in your app, without an external workflow tool.
- **You need inbound mail**, reply handling or inboxes for AI agents.
- **You don't want to run a separate SMTP provider.** Reloop includes the MTA, or you can use it hosted.

## Using them together

You don't have to choose. Listmonk can send through Reloop like any SMTP server:

1. **Verify your sending domain in Reloop.** Publish the DKIM record (`reloop._domainkey`) and merge `include:reloop.sh` into your SPF record.
2. **Create an API key** in the Reloop dashboard (it starts with `rl_`).
3. **In Listmonk, go to Settings → SMTP** and add a server:
   - Host: `smtp.reloop.sh`
   - Port: `587` with STARTTLS
   - Username and password: your Reloop API key
4. **Send a test campaign** to yourself and check the message in Reloop's logs.
5. **Forward bounces.** Reloop isn't one of Listmonk's built-in bounce providers, so subscribe a small handler to Reloop's `email.bounced` and `email.complained` webhooks and post them to Listmonk's `/webhooks/bounce` endpoint.

Listmonk keeps the newsletter UI your team knows, and Reloop handles delivery, transactional mail and inboxes.

## Switching from Listmonk to Reloop

If you'd rather run one system:

1. **Export subscribers** from Listmonk with their attributes and list memberships.
2. **Import them as contacts** in Reloop, mapping lists to groups or subscription channels and attributes to contact properties. Keep blocklisted and unsubscribed addresses suppressed.
3. **Recreate templates.** Change Go template expressions like `{{ .Subscriber.FirstName }}` to triple-brace variables such as `{{{first_name}}}`.
4. **Swap transactional calls** from `POST /api/tx` to `reloop.mail.send`.
5. **Rebuild recurring flows** as Reloop automations triggered by events from your app.
6. **Send a small campaign first**, watch bounce and complaint rates, then move the rest.
