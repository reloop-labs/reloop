## What an email-capable agent looks like

Modern LLMs support tool calling — you define a function, describe it in natural language, and the model decides when and how to call it. Wiring `send_email` as a tool turns any LLM into an agent that can compose, address, and dispatch email without a human in the loop.

## Defining the send_email tool

```typescript
const tools = {
  send_email: {
    description: "Send an email to one or more recipients.",
    parameters: z.object({
      to: z.string().email(),
      subject: z.string(),
      body: z.string(),
    }),
    execute: async ({ to, subject, body }) => {
      await reloop.emails.send({
        from: "agent@yourdomain.com",
        to,
        subject,
        html: `<p>${body}</p>`,
      });
      return { sent: true };
    },
  },
};
```

## Building the agent loop

The agent loop runs until the model stops requesting tool calls. Each iteration feeds previous tool results back as context so the model can reason about whether the task is complete.

## Guardrails you need

- **Allowlist recipients** — never let the agent send to arbitrary addresses without approval.
- **Rate limiting** — cap the number of emails per agent session.
- **Human-in-the-loop for bulk** — any send to more than one recipient should require confirmation.

## Real-world use cases

- Customer support agent that drafts and sends resolution emails
- Scheduling assistant that confirms meetings via email
- Onboarding bot that triggers personalized welcome sequences
